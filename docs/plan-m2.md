```bash
git -C <guoapp 镜像> fetch origin main
git -C <guoapp 镜像> rev-parse origin/main
```

统计提交距离前先确认不是浅克隆，否则数字会失真（本仓库踩过一次）：

```bash
git -C <guoapp 镜像> rev-parse --is-shallow-repository   # 必须是 false
```

## 4. 顺序与依赖

1. M2-0a、M2-0b 先落：两者各自一条提交能收口，且 M2-0b 会动规格，越早越好。
2. 再落 M2-0c、M2-0d：详情页依赖路由参数与数据层，顺序反了会返工。
3. 然后 M2-1 外壳，之后按 首页 → 探索 → 搜索 → 详情 → 追剧 → 历史 → 我的 推进。
4. 追剧与历史依赖同一个进度模型，两者必须共用一份数据结构。

## 6. 红线与未覆盖

- **红线**：M2 全部数据来自本地 fixture，不请求真实站源；真源联调在个人设备上进行。模块 JavaScript 只做静态阅读，不在公司机器上执行对真实站点的请求。
- **未决**：v1 的单源（红果）本身是 api v1 的 JavaScript 模块，"模块系统整层不做"因此不成立；最小必需形态（goja 宿主 + 清单与脚本加载 + 内置模块定位）的取舍与估算待拍板后补进本文件。
- **未覆盖**：播放、弹幕、下载、投屏不在 M2；界面视觉回归没有截图对比机制；macOS 全部未真机验证。
